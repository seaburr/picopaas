Tiny hosting for throwaway projects

Run a Docker container on the web in a minute. Give us a public image and a port; you get an HTTPS URL, plus an optional MySQL database and S3-compatible storage bucket. Built for demos, experiments, and class projects.

Request accessLog in

Images must be public and run as non-root. Access is approved manually.

What it is

One container

Bring any public Docker image and tell us its port. Set env vars and encrypted secrets in the dashboard, YAML, or CLI.

Optional database and storage

Tick a box to get a private MySQL database and an S3-compatible bucket. Map their connection details to env vars for your app.

HTTPS included

Every app gets a generated subdomain and an automatic Let’s Encrypt certificate.

Also included

  • Templates. Ghost, an nginx static-site starter and a podinfo sample API prefill the new-app form.
  • Rollback. The last few image versions are kept; roll back in one click. A new image that fails to start is automatically reverted to the last working one.
  • Resource history. Recent CPU and memory usage per app, shown as sparklines.
  • Logs and restarts. View and download logs, restart from the dashboard. Images are pinned by digest; floating tags like :latest are re-checked and redeployed when they change.

How it works

1

Request access

Sign up with your email. If approved, a platform admin will reach out, usually within a day.

2

Create an app

Image, port, env vars, and a database or bucket if you need one.

3

Open your URL

Live in about a minute over HTTPS. Edit the config to redeploy.

You’ll need a public Docker image that doesn’t run as root.

# 1. push an image to any public registry
docker push ghcr.io/you/app:1.0
# 2. create an app: image ghcr.io/you/app:1.0, port 8080
# 3. open the URL we generate
https://<generated-name>.raisehellpraisedale.xyz
