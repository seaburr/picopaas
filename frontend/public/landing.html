More about Kaisen

What you get

A real database

PostgreSQL or MySQL, your pick. One checkbox and it’s created, connected and ready. No server to babysit.

Somewhere to put files

Object Storage (an S3-compatible bucket) for uploads, or Block Storage, a small persistent volume, for apps that keep files on disk.

Backups that just happen

Turn them on once. Daily or weekly copies of your data are kept off-site, and you can download one whenever you like.

Your own address

Every app gets a secure URL automatically. Point your own domain at it when you’re ready.

Room to experiment

Deploys are one click to undo. Apps are walled off from each other. Logs, status and recent CPU and memory are one page away.

Secret-hunting bots turned away

Scanners looking for leaked .env files, Git folders and database dumps are stopped before they reach your app. It’s on for every app, with a list based on the OWASP Core Rule Set.

Work with others

Share apps in a team project. Use the CLI or an API key if you’d rather script it.

Kaisen: describe it, then use itPreview

Kaisen is an AI builder that lives inside PicoPaaS. You describe a small app, it builds and runs it, and you keep steering in plain language. What it makes is an ordinary PicoPaaS app, with the same address, database and backups as any other.

Built, tested, live

Kaisen writes tests for what it builds and runs them before your app starts. Each run ends with a package check that pushes the build onto the latest stable versions. You see the results with each build.

Data when you need it

Ask for a PostgreSQL or MySQL database, Object Storage or Block Storage and it’s wired in for you.

You hold the reins

Use your own Anthropic key and cap what a run, a day or a build can spend. Web access is off until you turn it on.

The code is yours

Download it any time, or have each build pushed to GitHub. Roll back to an earlier version if a change goes sideways.

Best for small web apps. Email, background workers and scheduled jobs aren’t supported yet. How Kaisen works

These are the defaults, and they’re small on purpose. You can set an app's CPU, memory, temporary disk and bucket size lower to suit it, and an admin can raise the ceiling for an app that needs more. PicoPaaS is for things you can afford to lose, not for anything you depend on.

Good to know

Can I run a production service here?

No. This is a dev and test platform with no uptime guarantee. Please don’t store personal data.

Which databases are supported?

PostgreSQL and MySQL. Choose one per app when you add a database. Once added, a database can’t be switched or removed.

Can my app send email?

Not over SMTP; outbound mail ports are blocked. Use a mail provider’s HTTPS API instead.

Who restores a backup?

For now an admin does it for you. You can download any backup yourself.
