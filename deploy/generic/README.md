# deploy/generic: PicoPaaS on any Kubernetes (local first)

The "generic" target (`CLOUD_PROVIDER=generic`, docs/PORTABILITY_PLAN.md P2): no cloud APIs at all. Everything runs
in-cluster, single replica, sized for a laptop. It is also the base for the kind-based CI e2e (P2c).

| Piece | What | Where |
|-------|------|-------|
| PostgreSQL 16 | TLS only (`hostssl`), non-superuser `picopaas_admin` (CREATEROLE, CREATEDB, owns `postgres`) | `data/postgres.yaml` |
| MySQL 8.4 | reuses `deploy/mysql/statefulset.yaml` (picopaas_ops procedures), TLS required, patched for `hostpath` | `data/kustomization.yaml`, `data/mysql.patch.yaml` |
| Garage v2.5.0 | single node, replication 1, layout + platform S3 key set by Job `garage-setup` through the admin API v2 | `data/garage.yaml`, `data/garage-setup-job.yaml` |
| Traefik 42.0.0 | Helm, LoadBalancer on `localhost:80`, plain HTTP | `traefik-values.yaml` |
| metrics-server 3.14.0 | Helm, `--kubelet-insecure-tls` | `metrics-server-values.yaml` |
| Platform | `deploy/platform` RBAC/Service/Deployment reused, 1 replica, image `picopaas:local`, own plain-HTTP Ingress | `platform/` |

Platform metadata DB: database `picopaas` in the same MySQL (user `picopaas`, `REQUIRE SSL`, `?ssl_ca=`). Both DbServers
(`primary` MySQL, `primary-pg`) are registered by `BOOTSTRAP_DB_*` / `BOOTSTRAP_PG_*`.

## Prerequisites

- Docker Desktop with Kubernetes enabled (verified on engine 29.9.2: a kind-based node, k8s v1.36.1, kindnet, StorageClasses
  `hostpath` and `standard`, both local-path), or kind itself (`kind-*` context; needs a `hostpath` StorageClass or the
  `storageClassName` patches changed).
- `kubectl`, `helm`, `docker`, `openssl`, `curl`. Free host port 80 (or `TRAEFIK_HTTP_PORT=8080`).
- ~2 GB RAM free for the stack.

## Up / down

```bash
export KUBECONFIG=/path/to/kubeconfig-with-only-the-local-context   # REQUIRED, the scripts never fall back to ~/.kube/config
scripts/dev/local-up.sh              # everything (first run: image build + pulls, ~10 min)
scripts/dev/local-up.sh --deps-only  # no platform Deployment
scripts/dev/local-up.sh verify       # dependency checks only
SKIP_BUILD=1 scripts/dev/local-up.sh # reuse picopaas:local
scripts/dev/local-down.sh            # remove everything (--keep-data keeps picopaas-data: DB/Garage volumes + secrets)
curl -H 'Host: platform.localhost' http://localhost/healthz     # or open http://platform.localhost/
```

Both scripts refuse unless the current context is `docker-desktop` or `kind-*` AND the API server is on localhost.
Re-running `local-up.sh` is safe: secrets and the CA are created once and reused; `picopaas-env` is rebuilt from them;
the platform rolls only when the env or the image changed.

`APP_DOMAIN=localhost`: apps get `<name>.localhost` (resolves to 127.0.0.1 in browsers and curl). Session cookies are
`Secure`, which browsers allow on `localhost` names but Safari may not.

## Secrets and TLS

Generated by `local-up.sh` and created straight in the cluster, never written to the repo or disk: `mysql-root`, `pg-admin`,
`garage-secrets`, `db-tls` (ns `picopaas-data`); `picopaas-keys`, `picopaas-env`, `picopaas-db-ca` (ns `picopaas-system`).
`db-tls` holds a self-signed CA (CA key discarded after signing) and one server cert for both DB services; the platform
connects with `verify-full` (PG, `BOOTSTRAP_PG_CA`) and CA-verified MySQL (`MYSQL_SSL_CA`), so the `db.ca_file` path is exercised.
Ingress is plain HTTP: no cert-manager, no ClusterIssuer (decision: a local wildcard cert adds nothing the DB TLS does not already prove).

## Known gaps

- **NetworkPolicy** is enforced by kindnet on the current Docker Desktop (kind-based) cluster (not on the old v1.31 one). A Service
  ClusterIP /32 allow is not honoured there (evaluated after DNAT), so the platform now uses namespace+pod selectors
  (`*_EGRESS_MODE=in-cluster`, set by `local-up.sh`). `deploy/platform/backup.yaml`'s `allow-egress-db` still uses CIDRs, so
  `local-up.sh` overrides it with `platform/backup-db-egress.yaml`; the base file needs an in-cluster variant for real installs.
- Self-signed TLS everywhere; no ingress TLS; custom domains off (`CUSTOM_DOMAINS_ENABLED=0`); Kaisen, backups and
  platform backups off (`BACKUPS_ENABLED=0`; `BACKUP_ENDPOINT` is set for when they are switched on).
- **DbServer flavor**: `BOOTSTRAP_*` cannot set `flavor`, so `local-up.sh` runs `UPDATE db_servers SET flavor='self-managed'`
  on the platform DB. Follow-up for backend-dev: `BOOTSTRAP_DB_FLAVOR` / `BOOTSTRAP_PG_FLAVOR`. (Admin API `PATCH` also works.)
- **arm64 / cryptography**: on the OLD Docker Desktop VM (engine 27.5.1) the repo image's `cryptography==50.0.2` aarch64
  wheel crashed with "Illegal instruction". Not reproduced on engine 29.9.2, so the workaround is now opt-in:
  `ARM64_CRYPTO_FIX=1 scripts/dev/local-up.sh` applies `Dockerfile.arm64-fix` (pins 46.0.5).
- **PostgreSQL 16**: the platform now grants itself SET ROLE on app roles (verified with the setting reset). The init script and
  `local-up.sh` still set `createrole_self_grant` as belt and braces; it can be dropped.
- **Image refresh**: a rebuilt image under the same tag is NOT picked up by the kind node; `local-up.sh` deploys a per-build tag
  `picopaas:build-<id>`.
- **Backup downloads**: the presigned URL points at `http://garage.picopaas-data.svc:3900/...`, reachable only inside the cluster
  (verified from the platform pod, 1181-byte package). From the host it needs a Garage endpoint reachable under that name.
- **Backups**: enabled (`BACKUPS_ENABLED=1`, `BACKUP_KEY_SCOPED=1`) against a Garage bucket `picopaas-backups` with its own
  read/write key. The published backup image is amd64 only and the node's containerd refuses it ("no match for platform in manifest",
  ImagePullBackOff), so on arm64 `local-up.sh` builds `picopaas-backup:local-arm64` from a temp copy of `images/backup` with
  arm64 restic/s5cmd and sets `BACKUP_IMAGE`.
- `PG_EGRESS_CIDR` is the Postgres ClusterIP/32 captured at first run; MySQL uses `MYSQL_EGRESS_MODE=in-cluster`.
- `kubectl apply` of the StatefulSets reports "configured" every run (server defaults vs. patch); harmless, no restart.
- Garage has no replication or backup; the hostpath volumes live in Docker Desktop's VM.

## Rollback

`scripts/dev/local-down.sh` (add `--keep-data` to preserve data). Nothing outside the local cluster is touched. Cost: $0.

## Getting tokens (testers)

The first account registered becomes platform admin; later signups are `pending` until the admin approves them. The session
cookie is `Secure`, so over plain HTTP send it by hand (curl will not):
```
H='Host: platform.localhost'; J='Content-Type: application/json'
curl -H "$H" -H "$J" -X POST http://localhost/auth/register -d '{"email":"admin@example.com","password":"<12+ chars>","accept_terms":true}'  # first = admin
curl -H "$H" -H "$J" -X POST http://localhost/auth/register -d '{"email":"user@example.com","password":"<12+ chars>","accept_terms":true}'   # pending
# log in and read Set-Cookie: session=...   (emails must not be on special-use domains such as .test)
curl -si -H "$H" -H "$J" -X POST http://localhost/auth/login -d '{"email":"admin@example.com","password":"..."}' | grep -i '^set-cookie'
curl -H "$H" -H "Cookie: session=<admin>" -X POST http://localhost/admin/users/2/approve
curl -H "$H" -H "$J" -H "Cookie: session=<user>" -X POST http://localhost/api/keys -d '{"name":"qa"}'   # -> {"key":"pp_sk_..."}
```
Then `Authorization: Bearer pp_sk_...` works for the API (keep the `Host: platform.localhost` header).
