Suspensions: UI mockup

Static mockup for docs/design/suspensions.md. Same tokens, card, row, badge, alert and dialog patterns as the shipped admin page. Each screen is shown at desktop (about 1100px) and phone (390px) width. Dashed outlines and blue notes are mockup annotations, not UI.

1. Admin: Suspensions tab

Decisions
  • New tab sits after Projects, with a count of suspended items (like Users and Apps). Link: /admin?tab=suspensions.
  • One list, newest first. Rows are users, projects and individually suspended apps. Apps stopped because a project or user is suspended are not top-level rows (a big project would flood the list). They sit under their cause behind an "N apps stopped" toggle.
  • Those child rows have no Unsuspend button. The action cell says "Unsuspend the project" (or user) and jumps to the parent row.
  • A suspended user's personal project is not a separate row; the user row notes it is included.
  • Name links: project to /projects/:id, app to /apps/:id, user to the Users tab filtered by email.
  • Unsuspend is a visible text button here (the one job of this tab); icon-only is used on the other tabs. It opens the Unsuspend dialog (section 3).

2. Admin: Projects tab gains "Suspend project"

Decisions
  • A Ban icon button at the end of each row, same icon, position and label pattern as Users ("Suspend <name>"). Suspended rows get the red "Suspended" badge, a one-line reason, and a Play (Unsuspend) icon instead.
  • On phone the icon moves under the app-limit field, in the same row.
  • Personal projects are not listed here (they follow the user), as today.

3. Dialogs (ConfirmDialog, max-w-sm, content in its slot)

Decisions
  • Suspend project: danger-solid button, reason textarea required (button disabled until filled). No type-the-name: the house style reserves that for irreversible deletes, and suspend is fully reversible (same as suspend user and suspend app today). Open question 1 asks whether you want it for projects anyway.
  • The dialog names the app count and the Kaisen effect up front, then what still works for members, so the admin knows the blast radius.
  • Unsuspend project: primary (not danger) button, no reason field. It says apps that were suspended on their own stay suspended.
  • Suspend user: same textarea, marked optional (as you asked), help text says where it shows. Message keeps today's wording plus the Kaisen line. If the design stays "reason required for every suspension", drop "(optional)" and disable the button.

4. Banner members see in a suspended project

Decisions
  • Amber (the existing warn tone) with a thicker left edge, not red: it is a state, not an error the member caused. It sits first in <main>, above the page title, and is the same component on the project page, every app page of the project (health and settings) and the Kaisen pages.
  • Two short rows: Blocked and Still works, then the admin's reason. The reason is shown to project owners only (per the design); other members see "Ask a project owner or the platform admin."
  • Write buttons stay visible but disabled (disabled plus a "Project is suspended" tooltip and a reason in the banner), so people see what they can't do instead of hunting for it. Danger zone (delete) is disabled too; the 403 from the API is the real guard.
  • Status badge on apps reads "Suspended" (existing StatusBadge). "Still works" lists downloading backups on the assumption that reads are allowed (design: reads allowed, restores refused). Open question 2.

Open questions

  • 1. Type-the-name on Suspend project? Mockup says no (reversible, like user/app suspend). Adding it is one prop.
  • 2. May suspended-project members download backups? Mockup says yes (read). Easy to remove from the banner and disable the button if not.
  • 3. Reason on user suspend: you said optional, the design doc says every suspension takes a required reason. Mockup shows optional.
  • 4. Should the reason be visible to all members or owners only? Mockup follows the design (owners only).
  • 5. Old suspended apps have no reason; mockup shows "No reason recorded" and still offers Unsuspend.
